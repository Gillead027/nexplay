# DISCORD_INTERACTION_MATRIX.md

Matriz mestra das interações do NexPlay: uma linha por ficha de `DISCORD_UI_ATLAS.md` (roteiros 0 a 16, 231 interações; uma ficha de referência que repete um ID já existente, como FRIEND_REQUEST_BADGE no Roteiro 14, não gera linha nova). O detalhe campo a campo de cada linha está na ficha de mesmo ID no Atlas; a hierarquia de telas está em `DISCORD_NAVIGATION_TREE.md`.

**Como ler**
- Colunas: ID, Tela, Caminho, Elemento, Trigger, Estado inicial, Ação, Feedback visual, Feedback sonoro, Resultado, Realtime, Persistência, Permissão, Shortcut, Erros.
- `—` significa que o campo não se aplica a essa interação. `Não confirmado` significa que o código lido não respondeu à pergunta e ela está listada como pendência no Atlas.
- Linhas de funcionalidade que **não existe** (`MISSING` no Atlas) descrevem o que era esperado e começam o campo Estado inicial com "Não existe".
- Persistência: "banco" é o SQLite da API, "localStorage" é por navegador/dispositivo (não viaja entre contas), "nenhuma" é estado que se perde em F5.
- Permissão: nome do bit de `Permission` quando exigido, `dono` para o dono do servidor, `—` quando qualquer usuário autenticado pode.
- Onde a coluna Realtime cita `LiveKit`, o evento vem do transporte WebRTC da sala de voz, não do WebSocket de dados do NexPlay.
